## 身份
多宠家庭专属 AI 健康记录工具（微信小程序）。核心体验：点底部中央「＋」进录入页说一句自然语言（或语音转文字），AI 自动提取宠物身份 / 时间 / 健康事件 / 用药 / 体重，归档到对应宠物的健康时间线。「像记账一样简单记录宠物健康」。

## 使命 / 解决什么问题
开发者本人为深度多宠家庭（7 猫 2 狗），真实痛点：
- 记录流程繁琐，急救场景来不及录入（记事本 / Notion 都太重）。
- 多宠信息零散，就医时无法快速提供完整病史。
- 体重数据无法跟踪曲线；家庭药品库存（尤其驱虫药）无过期管理。
- 市面产品要么表单繁琐多宠体验差，要么聚焦 AI 问诊忽视长期档案沉淀且有医疗合规风险。

## 三阶段演进（同一需求 · 三个工具范式）
- **v1**（2025.09–2026.01 · Cursor + uni-app + uniCloud）：4 小时 MVP，uniCloud 内测过，空间没续费下线。仓库 Cursor-PetsLog。
- **v2**（2026.01–2026.03 · OpenClaw 重构）：本质是系统学 OpenClaw 的载体（单 Agent 长期记忆 / 多 Agent 协作）。8000 行 / 双端 / CI/CD，未上生产。仓库 OpenClaw-PetsLog。
- **v3**（2026.04 起 · 本仓库）：范式反思落在**录入方式**：从「选宠物-选日期-填表」简化为「一句自然语言 → AI 解析」。**保留小程序及其 UI**（宠物卡片 / 时间线 / 药品库存），砍掉的是填表交互，不是前端。

## Non-Goals（明确不做）
- **不做医疗诊断 / 处方 / 医疗建议**：严守工具属性（记录·整理·溯源·辅助），规避合规风险。
- **不做社交 / 电商 / 宠物问诊**：聚焦记录 + AI 解析 + 药品管理。
- **v3 不是「砍掉小程序直连 Notion / 微信机器人」**：那是简历叙事的过度演绎；落地方案仍是小程序 + 微信云开发。详见 DECISIONS ADR-001。
- MVP 不做支付 / 会员（免费内测优先），会员体系在核心功能稳定后再上。

## 绝不 / Hard Constraints（红线）
- **绝不触碰医疗边界**：不诊断、不开方、明确标注「仅记录、不替代专业兽医」。
- **宠物范围 = 猫狗为主 + 常见宠物（A 档通用记录，ADR-023）**：猫狗保留完整医疗语义；兔 / 小宠 / 鸟 / 爬宠 / 鱼 / 其他走同一套统一记录模型（不为每物种定制医疗）。每物种定制医疗语义（B 档）见 ROADMAP，本阶段不做。（原「对外仅猫狗」红线已由 ADR-023 解除，向前改不动历史。）
- **绝不在前端放 LLM API key**：LLM 调用一律走云函数后端，key 存云函数环境变量。
- **绝不暴露用户隐私**：遵守《个人信息保护法》《网络安全法》。
- **绝不把 LLM API Key 写进仓库**：ARK_API_KEY 走 config.local.js / 云函数环境变量（不入库），见 DEPLOYMENT。
